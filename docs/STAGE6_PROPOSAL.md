# 階段6提案：任意Dataset的實際分析流程

狀態：使用者已回覆「階段 6 go」授權，以下本機API、前端整合與驗證已完成；結果見STAGE6_RESULTS.md。公開發布／加分驗收仍在階段8，外部寫入另需preview確認。

## 目標與使用流程

把現有網站的Custom Dataset區塊接上真正的Python引擎。使用者上傳CSV或輸入公開HTTPS CSV網址後，可以預覽資料、選Target／排除欄位、確認X／y，再依序執行基準與五種選擇方法，取得真實評估、區間、診斷、單筆預測與下載。不能只顯示CSV或換成預製JSON。

採已確認的一般Python核心＋FastAPI薄層，不建立使用者結果資料庫。每次分析請求自足，瀏覽器暫存本次結果；重新整理後不保證保留，提供下載並說明資料處理範圍。

## 修改範圍與預定產出

本機L7專案內新增CSV／URL載入、資料驗證、固定切分、API與回傳schema，以及必要的前端自訂流程、錯誤／進度與測試。沿用目前runtime、鎖檔及l7_analysis，不改既有36正式模型與階段4test成績；保留靜態正式兩題，即使自訂工作失敗仍可閱讀。

預定API責任為：資料載入／預覽、基準分析、指定選擇方法分析。實際路徑在實作時統一；每個結果附資料hash、Target、排除欄位、seed、方法、切分及版本，避免換資料／換Target後混入舊結果。

## A. CSV載入與設定

- [x] 支援檔案上傳與真正公開HTTPS CSV網址，不把Kaggle網頁當成CSV。
- [x] 顯示預覽、筆數、欄位、型態、缺值、重複與高基數提示；使用者指定數值Target、排除ID／洩漏欄位及必要類別型態。
- [x] 原始輸入14～39符合正式題目口徑；支援較少欄位的教學例子並清楚標記。Target／排除欄位不計入X，類別展開維度另列。
- [x] 依既有預算：原始內容≤3,500,000 bytes、50～10,000列、原始X≤39、encoded≤64（不含截距）、單一類別欄≤20類；超限明確拒絕，不靜默抽樣／截欄。
- [x] Target缺值、非數值、無限值或常數時給具體錯誤；不填補Target。X缺值依各training fold填補並回報。
- [x] 對重複X／群組保持split與CV隔離；固定同一來源與設定的切分，所有方法共用同一保留test，不為分數重切。

## B. 公開網址取得與資料隔離

- [x] 只接受公開HTTPS；限制時間、內容長度、串流讀取及redirect次數，不執行上傳程式或反序列化模型。
- [x] 每一跳都核對host、DNS及實際連線目標，拒絕loopback、private、link-local等內部位址；防止只查一次DNS後重新解析至內網的落差。
- [x] 正確驗證原host TLS憑證，不繞過驗證；不轉送使用者cookie、token或憑證。URL中的登入資訊與非CSV頁面明確拒絕。
- [x] 上傳資料只用於本次運算，不寫入Git、NotebookLM、公開報告或使用者歷史資料庫；log不包含資料列或敏感URL參數。

## C. 分方法的真實分析

- [x] 基準含Dummy／全特徵OLS及Ridge／Lasso預測比較；五選擇方法各自請求，仍使用共用引擎與training-only前處理／選擇／CV。
- [x] 實際執行預先公布的k／參數網格與CV設定；不在限時時默默少跑方法。正式兩題與自訂分析的設定差異若有，必須明示並驗證。
- [x] 每方法預算120秒協作deadline；本機驗證後續Vercel候選240秒請求設計，不把本機測量當雲端保證。
- [x] 依development CV選定該方法模型，再作固定test評估；方法比較不依test重選「最佳」主代表。JSON回應有完整／逾時／失敗／取消等清楚狀態。
- [x] 回傳MAE／MSE／RMSE／R²、選取欄位、公式、模型、適用OLS CI／PI、覆蓋／寬度與診斷。rank／自由度／零殘差變異不足時明確不可推論，不硬算。
- [x] 每回應≤3,000,000 bytes；圖最多1,000顯示點（回應超限時可縮為250點），指標與覆蓋使用完整保留資料。超限需調整顯示／序列化，不能改動計分資料。

## D. 網站狀態與互動

- [x] 依序送出基準與五方法，顯示真實queued／running／succeeded／failed／cancelled；只有成功回應才勾選完成。
- [x] 單瀏覽器一次一個方法，instance忙碌時明確回應；不把instance互斥宣稱平台全域只會有一個工作。
- [x] 支援重試與取消。取消停止後續請求及前端等待，已執行的數值求解由deadline／檢查點結束，不宣稱已立即殺掉伺服器程序。
- [x] 換檔案、Target或排除欄位會隔離舊結果；失敗時保留有來源綁定的已完成方法，不假稱整套完成。
- [x] 單筆預測與下載使用本次真正模型；數值／類別、未知值、缺值、外推及區間限制沿用現有驗證原則。
- [x] 正式兩題及自訂結果分開，錯誤不破壞既有展示；桌面／手機／鍵盤流程可操作。

## E. 驗證與下一階段提案

- [x] 選一份未放入正式兩題的真實公開回歸資料，記錄來源與授權；透過真實HTTPS取得及瀏覽器上傳兩條路徑完成分析。
- [x] 同CSV／設定的本機引擎與HTTP／網站結果一致；換Target、排除欄位後結果與來源指紋確實更新。
- [x] 真實localhost API成功與瀏覽器完整流程分開記錄；URL失敗、redirect、私有位址、大小／時間超限、忙碌、取消等以適當的受控測試驗證，模擬不冒稱遠端成功。
- [x] 檢查全方法、完整／部分結果、區間不可用、下載與單筆推論；保存實際回應、來源及畫面，不保存使用者私密資料。
- [x] 更新README、資料契約、checklist、驗證報告與階段7提案；NotebookLM實際研究仍由使用者登入執行，Agent準備與整合。

## 驗收界線

階段6需在本機網站實際跑完第三份新資料的上傳與URL流程，且使用相同分析核心，不能只有API草稿。公開Vercel runtime、build大小、冷啟動、遠端新資料操作與最終加分證據仍在階段8；若平台不能承接完整需求，先提出具體替代方案與成本，不默默取消方法或加分。
